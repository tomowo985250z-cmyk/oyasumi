# 猫のごはん・おやつ ローカル確認

現在のUIは、自分の猫とごはん操作をホームに集約。マイページには小さいプロフィールアイコンを残す。他の猫へのおやつは従来どおりプロフィールから贈る。

最終回帰テストは `npm run test:cat-care`。メモリ内DBで旧仕様・朝夕2枠のSQLを検証した後、実際のアプリをローカルAPIに接続してWebKit／Edgeで確認する。本番DBには接続しない。Playwright Coreの場所は `OYASUMI_PLAYWRIGHT_PATH`、Edgeの実行ファイルは `EDGE_PATH` で指定可能。

- 320／375／390／430px、昼夜・明暗表示、全16種類の猫の食事前・食事中・食事後。
- 就寝投稿後の寝姿、翌06:00の解除、12:00の給餌枠切替、就寝後の閲覧・リアクション・投稿変更。
- 自動更新中も同じアニメーションを維持。連打・保存中の移動・再訪問・サーバー確認済みの重複・通信失敗後の再試行。
- 画像読込中も通常の猫を表示。画像読込中または非表示中に画面を離れたら、待機・再生処理を解放する。
- 食事は可視時間で6秒。食事前1秒、食事中3秒、食事後2秒とし、末尾200msで現在の通常／寝姿へ戻す。動きを減らす設定も6秒を維持。

6秒演出の調査で、通常の猫を画像デコード前に隠す経路と、非表示中の画面離脱でフェーズタイマーが停止したまま再生状態が残る経路を確認した。表示切替を再生開始後へ移し、画像待機中・再生中の両方でDOMからの離脱を監視して終了させる。非表示イベントの重複でも経過時間を二重加算しない。

以下は旧給餌仕様のメモリ内DBを使う手動プレビュー。

`node test-support/cat-care/serve.cjs` を起動して http://127.0.0.1:9390/ を開く。
Node 22 と package.json に記載の PGlite が必要。メモリ内の検証DBのみを使い、本番Supabaseには接続しない。終了時に検証データは消える。

- ごはん：日本時間の当日に「おやすみ」「寝てみる」「早めに寝る」を投稿した自分の猫へ1回。連続投稿は不要。
- おやつ：贈る側が日本時間の1日につき合計1回。他の猫限定。
- 届いたおやつ：本人に今日・累計と直近30日分の受取日別記録を表示。全日付の記録は保持。贈り主情報をクライアントに返さない。
- テーブルは直接読み書き不可。認証済みRPC内で権限・投稿条件・重複を検査。
- 約6秒の無音CSSアニメーション（お皿登場1秒・もぐもぐ3秒・食後の喜ぶ姿2秒）は承認済みPNGを再利用。ごはんは茶色いカリカリ、おやつは銀青色の小魚。「ごはんだよ」「おやつだよ」と食べ物の形・名前を食後も表示。動きを減らす設定でも6秒の静止画3段階表示。アプリが非表示の間は時計とCSSを停止し、復帰後に残りを表示。

現在のブラウザ回帰結果は `output/home-cat-care/`。旧プレビューのDB検証は `node test-cat-care-sql.cjs`。

ホームへの集約はクライアント側のみの変更。DB仕様・給餌枠・既存データ・7日制限解除設定は変更しない。接続先に給餌RPCがない場合も既存機能を継続する。
