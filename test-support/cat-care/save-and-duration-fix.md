# 保存と6秒表示の調査・修正

2026-10-10。iPhone実機には接続できないため、Windows版Playwright WebKitのタッチ入力とnavigator.standalone模擬で検証。実機Safari/インストール済みiOS PWAの検証とは区別する。

## 確認した問題

- 当日投稿がない場合、資格不足でボタンがdisabledになるが、以前は「ごはんをあげる」という表示のまま理由が空だった。ネイティブの無効ボタンはタップしてもclickを発火しない。日本時間0時以降の対象投稿が必要なことを常時表示し、ボタン名も理由に変更。
- 保存中も共有データ更新が描画でき、リクエスト開始時のカードが置換される経路があった。元カードのDOM同一性で保存結果を表示していたため、応答が届いても表示先が見つからなくなる。保存中の更新を保留し、開始前/終了前の古い読み取りはrevisionで破棄。完了時は所有者キーで現在のカードを探す。
- エラー理由は再確認RPC完了後まで表示されず、次の自動描画でも消えていた。失敗直後に画面へ出し、再描画後も保持する。資格、猫、RPC未検出、認証/権限、通信、タイムアウト、不正応答を区別。サーバーの生メッセージや認証情報は表示しない。
- 応答のstatusだけを検証し、finallyでacceptedのtruthy値を再生に使っていた。acceptedがbooleanで、対象の保存済みフラグがtrueの場合だけ完了として扱う。新規accepted=trueのみ再生。重複や確認不能は再生しない。保存確認は20秒、失敗後の状態再確認は5秒で打ち切る。ネットワーク側で遅れて保存された場合もサーバーの1日1回制限で保護される。
- 省モーション設定ではJSが0.9秒で表示を終了していた。通常/省モーションとも可視時間6秒へ統一し、省モーションは移動・回転なしの静止画3段階にする。CSS/JSの時間は1秒→3秒→2秒。visibilitychangeでJS時計とCSSを停止し、非表示時間を消費しない。
- 配信更新クライアントのcanReloadは食事の保存/再生を見ていなかった。保存中、画像準備中、再生中は更新によるページ再読込を保留する。

## 検証

`test-cat-care-save-webkit.cjs`: 実際のtap、無資格の説明、他の操作中、各RPCエラー、不正なaccepted/status、タイムアウト、保存中のカード置換と共有更新、通常/省モーションでの1/4/6秒の実時間計測、食後の種類表示、自動更新、1.5秒の非表示/復帰を通常/standalone模擬で検証。`output/cat-care-save/report.json` に可視時間の実測値を出力。

`test-cat-care-save-live-webkit.cjs`: 公開ページへ修正クライアントだけを差し替え、本番RPCに接続した隔離テストアカウントでタップ、資格判定、HTTP 200 + accepted=true + mealDone=true、6秒実測、再読込後の保存済み表示、7日制限解除を確認。通常/standalone模擬の各1アカウント。一時睡眠投稿は終了後に削除、検証用プロフィールと食事記録は保持。既存ユーザーの記録とDB構造・権限・制限設定は変更しない。

追加のNode診断でも本番RPCは当日投稿なしでP0040、当日投稿後にmealEligible=true、保存でaccepted=true/mealDone=trueと正常に返った。これだけで利用者の実機に起きた原因を一つに断定はしない。

本番RPC接続のWebKit実測は通常6.008秒、standalone模擬6.009秒。最終ローカル検証で通常/省モーションの実測は6.002〜6.011秒、非表示/復帰の可視時間は6.006〜6.007秒（非表示1.5秒は除外）。計測はCSSアニメーションのシークではなく、実際の表示開始から終了まで行った。実測JSONはoutputに保存する。

全16猫種の通常/standalone模擬・4画面幅は `test-cat-care-webkit.cjs`、既存機能は `test-cat-care-browser.cjs`。両者と保存テストは同じローカル検証DBをresetするため順番に実行する。本番接続テストはローカルDBへ影響しない。

画像224ファイルのハッシュ、食事SQLの1日1回・重複/競合拒否、猫種7日制限の一時解除、リリースとキャッシュ更新は既存テストで確認。SQL変更・適用は不要。
