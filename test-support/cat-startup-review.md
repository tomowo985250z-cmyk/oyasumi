# 猫の起動・タイムライン表示の高速化

集計・朝のリアクション・プロフィール・猫の状態を直列に待ち、最後に画像を読み始めていた。独立した読み取りを並列化し、自分の猫の現在のプロフィール・共通時計・睡眠状態が揃った時点でホームを先行表示する。投稿者プロフィールは20人ずつ、最大5バッチを並列取得し、確認できたアイコンから表示する。

同じ投稿者のプロフィールを初期化と一覧で重複取得しない。画像のデコード済みキャッシュは従来どおり最大12枚。永続キャッシュには認証ユーザー・プロジェクト／認証ストレージに結び付けた猫種だけを7日間保持し、画像の先読みに使う。表情・睡眠状態・時刻をキャッシュから表示することはない。

未確認の投稿者は画像を付けず表示領域を維持する。認証変更、画面復帰、投稿・給餌操作、06:00境界をまたいだ古い途中結果は表示しない。プロフィール未確認のアイコンから仮の猫のプロフィールを開くことも防ぐ。

## 計測結果

本番Supabaseの応答時間やiPhone実機の計測ではない。実際のアプリとAPI実装に、認証15ms・自分のプロフィール180ms・他のプロフィール100／650ms・任意集計700ms・画像180msの遅延を注入した隔離検証。修正前はcommit `dab00b8`を使用した。

| 指標 | WebKit | Edge |
| --- | ---: | ---: |
| 修正前：390px・PWA相当・初回ホーム猫 | 5,892ms | 5,510ms |
| 修正後：16条件の初回ホーム猫の中央値 | 1,710ms | 1,253ms |
| 修正後：同じ16条件の再読み込み中央値 | 1,239ms | 804ms |

別の同条件のAPI単体検証では2,215msから約598msに短縮。ブラウザの負荷によるばらつきがあり、実機の時間を保証する数値ではない。

`output/cat-startup/`に通信・プロフィールの開始時刻と所要時間、画像の読み込み／デコード時間、表示可能になってから実フレームに現れるまでの待ち時間を保存する。稼働中の画面でも、開発者ツールから `OyasumiAPI.timings` と `CatImages.timings` で直近の内訳を確認できる。診断値はメモリ内だけに保持し、外部へ送信しない。

## 回帰検証

`npm run test:cat-startup`：両ブラウザ各16条件（320／375／390／430px、通常／PWA相当、昼の起床／夜の就寝）で先行表示、投稿者バッチの順次表示、画像のフレーム監視、再読み込みを確認。

安全性テストは両ブラウザ各10条件：有効・古い猫種・別ユーザー・期限切れ・破損・保存不可のキャッシュ、睡眠取得失敗／保留、認証変更、復帰前の古い途中結果。

従来の誤表示防止テスト各40条件、給餌の6秒・二重操作・睡眠制限・06:00／12:00、頭の実描画、投稿／リアクションのAPI互換、既存画像ハッシュ、構文／リリース整合性も検証。本番DBへの接続・書き込みなし。iPhone実機は未検証、PWAと復帰はブラウザ上の模擬条件。
