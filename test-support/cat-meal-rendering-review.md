# 給餌の重複表示・頭の動きの修正

対象は猫の表示制御と給餌描画。ユーザーの端末条件は、iPhoneの「視差効果を減らす」がオン、ホーム画面から起動。DB・保存API・回数制限の変更は行わない。

## 実コードから確認した原因

修正前 `c0f9f87` のソースを使い、WebKitで描画状態と画像を採取した。

- 通常設定では、座り猫→食事猫の0.9〜1.08秒、食事猫→食後猫の3.9〜4.08秒に、猫全体の透明度を交差させていた。1秒時点で両者の実効opacityは0.444と0.556。異なる猫の輪郭が同時に表示される。
- 終了前5.8秒から通常猫を戻し、食後猫と0.2秒間重ねていた。低減設定ではフェードのアニメーション自体が無効になり、5.9秒で両方がopacity=1になる。[修正前の画像](../output/cat-meal-rendering/baseline-webkit-reduced/5900.png)。
- 復帰時の `data-cat-state-pending` / `data-cat-own-ready` のvisibility例外は、給餌中の通常猫を隠す指定を上書きできた。
- 低減設定では頭のCSSアニメーションも一括停止していた。同じ設定のWebKitで食事中の頭のY座標が一定になった。ホーム画面起動そのものの障害や、iPhone固有GPU障害と断定する根拠はない。

修正前の測定値は `output/cat-meal-rendering/baseline-webkit*/report.json`。再現は `node test-cat-meal-rendering.cjs --baseline --reduced`。このモードだけ、上記コミットの4ファイルをブラウザに配信する。

## 修正した表示制御

`DayRoom` が準備→食事→移動先の準備→通常表示を管理する。素材のdecode中は元の猫を表示し、開始時に通常猫を `hidden` / `display:none` にして食事へ切り替える。食事中の座り・咀嚼・食後は、同じ可視時間の時計から一つだけ表示する。猫全体同士のフェードは廃止した。

6秒の可視時間が終わった後、次の居場所・姿勢の画像を非表示の通常猫に用意し、decodeを待って背景と猫を同じ処理で切り替える。待機中に移動時刻をまたいだ場合は最新の姿勢を再確認する。画面を離れた場合は待機・監視・ロックを解除する。

頭は別のCSS時計を使わず、同じ可視時間からrAFで `top` を更新する。WebKitで画像の切り抜きと移動を分離しつつ、実際に再描画する。通常は12px、低減設定は3px・1秒周期の小さな上下運動とし、回転・拡大を使わない。背景・確認待ちでは段階・頭・餌の消費を一緒に停止する。

## 検証

```powershell
node test-cat-meal-boundaries.cjs
node test-cat-meal-boundaries.cjs --edge
node test-support/verify-cat-meal-release.cjs
node test-support/verify-cat-meal-release.cjs --edge
```

境界検証は各エンジンで全16猫種×320/375/390/430px×3居場所と夜明け×低減設定オン/オフの512再生。開始・1秒・4秒・5.8秒・6秒前後など15時点を調べ、食事中の居場所維持、終了後の最新居場所、各時点の猫が1つであることを確認する。食事とおやつを交互に使う。画像decode待ち・復帰確認中・その間の追加移動も別途検証する。

頭の動きは、3倍の画素密度で実時間のrAFから頭と胴の座標を連続採取し、胴が静止したまま頭が移動することを確認する。続けて、同じ再生時計を段階的に進めた3枚のブラウザ画像で頭部分のピクセル差を確認する。別テストでは6秒全体のrAF測定と連続撮影を分けて行い、rAFごとに猫の重複がないことも調べる。Windows版WebKitでは画像取得と高密度のソフトウェア描画がフレーム採取を妨げるため、この全区間測定は1倍の画素密度を使い、実際の再生開始イベントから採取する。撮影用の再生は追加の保存APIを呼ばない。失敗した測定も `continuous.json` に残す。CSSアニメーションの存在やtransform値だけでは合格にしない。

既存の給餌・おやつの保存応答と6秒再生、二重操作、回数制限、就寝、06:00/12:00境界、画面移動、画像読み込み待ち、復帰待ち、3居場所のホームと他人プロフィールの同期、夜猫、月の動き、投稿と保存、起動表示、画像ハッシュを回帰検証する。

結果と連続画像は `output/cat-meal-rendering/`、頭の拡大連続画像は `output/cat-meal-motion/local-webkit/` と `local-edge/`。本番APIはfixtureに置換し、検証中の本番DB通信・書き込みは0件。WebKitのモバイル・ホーム画面起動はエミュレーションで、実機iPhoneは未検証。
