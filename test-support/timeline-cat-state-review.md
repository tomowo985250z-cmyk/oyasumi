# 最新投稿と猫の状態の同期（2026-10-16）

## 確認した原因

保存RPCは「もう寝るよ」を `sleep`、「眠れないけど寝てみる」を `try-sleep` として保存し、取得も `event_order` 降順で投稿を選んでいた。表示までの経路には以下の不一致があった。

- `PostCatExpressions` が睡眠報告にも半開きの目・あくびを選択していた。取得済みの投稿が正しくても、タイムラインの猫が起きて見える。
- `profileRoomMarkup()` は `awake` と `sleep` 以外の状態を捨てていた。`try-sleep` と旧 `early-sleep` は時刻依存の姿勢へ戻っていた。
- `DayRoom` の睡眠優先は自分の猫だけに適用され、他の猫は `sleep` でも昼の行動を表示していた。
- 開いたプロフィールはクリック時の投稿オブジェクトを保持し、取得後もそのユーザーの新しい投稿へ差し替えていなかった。
- 取得にはローカル保存・復帰のrevisionガードがあったが、APIを並行利用した場合に古い取得全体と途中経過を無効にする世代管理がなかった。

画像キャッシュは画像の暖機に使われ、投稿状態の保存元ではない。DOMの画像再利用も画像・属性が完全に一致する場合だけだった。これらのキャッシュを削除しても、上記の状態判定は直らない。

## 修正

投稿状態を `PostCatExpressions.state()` で共通化した。`sleep`・`try-sleep`・旧 `early-sleep` はアイコンと他人の部屋でも睡眠状態を優先し、既存の閉じた目の画像・寝姿を使う。起きている2種類の報告は従来の表情候補と投稿IDによる安定した選択を維持する。画像の変更・生成はない。

公開表示と自分のアイコンは、現在の06:00区切り内の有効な投稿からユーザーごとの最新を選ぶ。`event_order` を優先し、同順序・順序なしの場合は時刻とIDで決める。未来・前夜・不正状態の投稿は表示対象から除く。元の履歴を削除・変更しない。

取得結果の反映時に、開いているプロフィールも同じユーザーの最新投稿へ更新する。別アカウントに切り替わった場合や対象が消えた場合は古いプロフィールを閉じる。通常の給餌中の画面保持は維持する。タイムラインへ移動するナビゲーションも再取得を要求する。表示中の別端末の変更は既存の30秒更新・画面復帰・再取得で反映する。

API取得は世代番号を持ち、新しい取得が始まった後の古い結果を `CAT_READ_SUPERSEDED` として拒否する。古い途中経過のコールバックも反映しない。ローカル保存・復帰・認証変更の既存revisionガードと併用し、HTTP取得も `cache: 'no-store'` とした。DB・RPC・保存データ・認証方式は変更しない。

## 検証方法

`npm run test:timeline-cats` を実行する。

- 単体検証：5,000投稿、2つの起床報告と全睡眠報告、投稿IDによる安定性、旧投稿、巨大な順序値、逆順の配列・矛盾する時刻、未来・前夜・不正状態の除外。
- `test-timeline-cat-state.cjs`：実際の `app.js` と `supabase-api.js` を使い、Supabaseの通信部分だけを共通のメモリ内検証データへ置換する。2つの独立したブラウザコンテキストから4種類の投稿を保存し、投稿直後の本人・別端末・開いたプロフィール・ナビゲーション・再読み込み・非表示復帰・BFCache相当復帰を確認する。
- 古いプロフィール取得を保留し、新しい取得が完了した後に解放する。古い全結果と途中経過の両方が拒否されることを確認する。復帰前の取得についてもアプリ側のrevisionガードを確認する。
- 各エンジン320／375／390／430px × 全16猫種 × 現行4報告と旧 `early-sleep` の計320条件。実際のタイムライン・画像decode・他人の部屋を確認し、睡眠報告では閉じた目と寝姿・室内の居場所が一致すること、横はみ出しがないことを検証する。

レポートと画像は `output/timeline-cat-state/{webkit,edge}/`。実機iPhoneや実際の他端末での試験ではなく、WebKit／Edgeのモバイル表示と2コンテキストによる検証。実アプリの投稿・取得処理を通すが、本番への接続・書き込みは行わない。
