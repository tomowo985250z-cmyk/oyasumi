# クリングルファーマ（4884）重要イベントモニター

`kringle/`だけで動く日本語の静的ページ。既存のおやすみ・CanBasの画面、音楽、取得データ、公開設定は変更しない。
実行時の外部ライブラリ・APIキーは不要。robots/googlebotはnoindex,nofollow,noarchive。

## 取得と確認の境界

- 公式IR：公式ページの`eir_v5.js`→`common_conf.js`が参照する4884の公開JSONP。コードを実行せずJSONとして解析。2025年以降の開示ID・表題・公表日時・公式リンク・カレンダーを保持する。動画や非公式の書き起こしは取り込まない。
- TDnet：公式日付一覧から初回は直近7日、その後は最終成功の前日以降を取得。すべてのページをたどり銘柄コード48840を抽出。31日を超えた未取得期間は取得範囲に警告を残す。取得済み開示は閲覧期間終了後も保持する。IRとの重複は表題＋公表日でまとめ、両方のリンクを表示する。
- jRCT：jRCT2031260281とjRCT2051220132の公開HTML。識別番号・所属会社・段階・募集状態・日付・予定人数の必須項目を検証。担当者・連絡先は保存しない。
- ClinicalTrials.gov：API v2、`filter.ids=NCT07722962,NCT05627648`。試験ID・スポンサー・開発コードを照合。予定人数を実登録人数に流用しない。ACTUAL/ESTIMATED、年月だけの日付も保持する。

公開配信データの仕様変更・通信拒否には失敗表示で対応する。非公開APIや認証回避は使用しない。
TDnetの有料APIやPDF原文の再配信は使用しない。公開ページは公式資料へのリンクと独自の短い要約のみ。

## PDF本文・開発段階の手動反映

`data/reviewed.json`は人が公式本文を確認した記録。毎日の取得処理では変更しない。
イベントごとに公式URL、公表日、該当ページ、確認日を記録する。
2026-11-21に11/11決算短信、11/17質疑応答、11/18発行条件決定の該当箇所を確認し初期登録した。
PDF解析用ツール・原文・PDFファイルは開発用作業領域だけにあり、公開ファイルやActionsの依存には含まない。

更新時は新しい公式資料を読み、該当イベントの既存IDを維持して日付・確度・進捗・詳細・出典・確認日を修正する。
`documents`に確認資料のURLと必要な別URLを記録する。自動検出した新着PDFは、確認後にここへ反映するまで本文確認待ち。
カレンダーを実施完了に更新する際は、同じ`calendar_...` IDの確認済みイベントとして記録する。
`node kringle/scripts/update.mjs`またはActions手動実行で変更前後を履歴に取り込む。

日付区分（確定・予定・未定）と進捗（進行中・完了・延期・未確認等）は独立。
予定時期の経過をもって完了・延期と判断しない。2027年前半は半年の範囲で管理し、架空の発表日を表示しない。
開発バーは公表された段階の位置。米国第Ⅲ相の開始準備・ALS追加解析を実施中の治験と区別する。
登録簿の記載は出典別のまま表示し、同義の募集終了表記は揃えて比較する。食い違いを自動で解消しない。

## データ保持・履歴

- `data/events.json`：各情報源の正常スナップショット、確認済み情報、直近差分、全変更履歴。内容変更時のみ保存。
- `data/status.json`：情報源別の試行日時、最終成功日時、ハッシュ、失敗理由、取得範囲。毎回更新。
- 初回記録は比較対象なし。新しく取得した掲載を新規契約や新規治験の成立とは解釈しない。
- 失敗した情報源は以前のデータと成功日時を保持。他の情報源は独立して更新できる。
- 必須項目欠落や未対応の状態は失敗扱い。ハッシュが合わない取得管理情報を成功日時として表示しない。
- 直近差分は変更なしの次回取得や失敗で消さず、同じ情報源の次の差分で置換する。過去の差分は履歴に残す。
- 変更日時が未公表のため、差分を初めて取得した日時を「取得確認日時」と表示する。

## 自動更新と公開

`.github/workflows/kringle-monitor.yml`は毎日13:47ごろ（日本時間）とworkflow_dispatch。
既存CanBasと同じconcurrencyグループを新しいワークフロー側で指定し、共有ブランチとPages公開を直列化する。
既存ワークフローは変更しない。コミット対象はkringleのevents/statusの2ファイルだけ。
一部取得失敗も状態を公開し、ジョブ結果は失敗にする。公開は既存の`canbas/scripts/pages-build.mjs`の純粋な公開関数を再利用する。
Pagesはmain直下・legacyの既存設定を検証し、期待するコミットの公開完了まで確認する。
重複ビルドの中断で旧ビルドAPIに失敗が残る場合は、対象コミットと一致するPages Actionsの配信成功を確認する。
別コミット・他のワークフローの成功を公開成功として扱わない。確認の補完はkringle側だけで行う。

```sh
node --test kringle/tests/update.test.mjs
node kringle/tests/browser.cjs
node kringle/scripts/update.mjs
```

ブラウザーテストは開発用Playwright WebKitを使用（`OYASUMI_PLAYWRIGHT`で既存インストールを指定可能）。
公開時・毎日の実行時には不要。375/390/1024px、フィルター、全履歴、変更保持、取得失敗、初回失敗、出典不一致、noindex、横あふれ、原文の安全な表示を確認する。
テスト用の状態変更を実際の取得データへ混ぜない。
