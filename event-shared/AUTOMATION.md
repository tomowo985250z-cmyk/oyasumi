# 公式資料の自動照合

既存の各社の日次Workflowで実行する。`reviewed.json` / `events-reviewed.json` は人が確認した入力として維持し、自動照合の根拠・キャッシュ・採用値は既存 `events.json` の `automation` に保存する。画面へ渡す `reviewed` は両者を合成した互換形式。取得試行・循環確認の時刻は既存status JSONの `automation` に分離する。

- 新規・変更資料だけをPoppler `pdftotext -bbox-layout` で解析する。OCRや生成AIは使わない。URLごとにETag／Last-Modifiedを利用し、200応答も本文SHA-256が同一なら再解析しない。
- 対象は人による確認日以降の公式IR／TDnetの関連PDFと、既存最新期以降のJoby株主資料。直近18件、1回6件まで。未取得を優先し、既取得も巡回する。1PDFは8MB、取得25秒、抽出30秒まで。
- 発行者の公式URL・リダイレクト先・本文の会社識別を確認する。臨床イベントは同一の短い段落内で治験ID、薬剤名、段階、明確な実績表現と日付が一致した場合だけ採用する。「予定」「申請準備」「開始承認」を試験開始・製造販売承認と混同しない。
- 対応する臨床IDは `TARGETS` に限定。CanBasはFUJI-PanC01／EU CT番号、クリングルは登録済み対象2試験。未登録の試験・資金調達・提携の自由記述等はルールで自動確定せず確認待ち。明記された製造販売承認申請と承認取得は別項目。
- 登録簿は対応する試験だけを反映する。CTISの国別実施情報は欧州試験全体へ「一部の参加国で開始」の意味で反映し、全施設の開始とは扱わない。ClinicalTrials.govとjRCTが不一致なら保持。試験終了は解析段階で、薬事承認ではない。
- Joby認証は対象期、基準日、本文の公表日、5段階の見出し、Joby／FAA凡例、位置関係の一致する10数値（0〜100％）を一括照合。FAA側もJoby公表値。総合進捗の推計、図形の長さからの補完はしない。新しい基準日の版のみ追加し、同一基準日の訂正版・矛盾は確認待ち。既存認証履歴を変更・削除しない。
- 根拠URL・ページ・抽出原文／登録項目・文書ハッシュ・基準日・公表日・自動照合日時を保存。自動照合は対象項目の照合であり、人による全文確認とは区別する。
- 不明、矛盾、後退、取得・抽出失敗では以前の採用値を保持する。既存の差分・強調・履歴へ合成結果を渡し、無変更の取得では変更マークを消さない。将来の資料レイアウト変更は確認待ちになる。

関連テスト：`node --test event-shared/automation.test.mjs` と既存3社テスト。PDF抽出ツールはActions環境だけに導入し、ブラウザーにPDF解析ライブラリーやAPIキーを配布しない。
