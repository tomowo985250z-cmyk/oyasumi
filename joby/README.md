# Joby FAA認証・イベントモニター

joby/と専用workflowのみ追加し、既存のゲーム・CanBas・kringleは変更しない。kringleのhash/differences、時系列区分、公開文字列の処理、Pages完了確認をimportして利用する。外部ライブラリ・ブラウザからの直接API取得・画像・PDF同梱は不要。

## 確認済み情報

data/reviewed.jsonが認証数値とイベント本文の確認記録。認証は基準日・公表日・本文確認日・資料ページと5段階×2系列を必須にする。FAA列も会社発表。総合率や認証完了時期は推計しない。Q2→Q3比較は公表資料間の履歴として初回取得と区別する。率の低下も記録し、延期・エラーと推定しない。

PDFやSEC添付資料を確認したら、新しいcertificationsを末尾に追加し、確認日・出典・該当ページを記録する。過去認証版は上書き・削除せず履歴として残す。periodはQ3 2026の形式で公表資料の対象期を記入。イベントは会社発表／規制当局確認と、実績／予定／未定、進行状況を別々に指定する。FAAを根拠にするイベントはFAA公式URL必須。SEC提出はFAA承認の根拠にしない。eIPP・TIA準備・試験飛行・型式証明・通常の商用運航を混同しない。

## 自動取得の範囲

- Joby公式IR RSS：公開日時・表題・リンク。現在のRSS掲載分と過去取得分を保持。
- 株主資料：公式決算ページの資料リンク・対象期。PDF本文や進捗率を自動採用しない。
- SEC：CIK1819848の公開Submissions JSON（APIキー不要）。User-Agentを明示して1回取得し、失敗時はJoby公式IRのSEC提出一覧の先頭ページから対象様式を代替検出する。代替成功はfallbackとして表示し、SEC直接成功日時は更新しない。両方失敗なら前の正常データを保持する。今回のローカル実通信では直接403・代替200。GitHub Actionsでは実際の結果を記録する。
- FAA：ニュース先頭にあるJoby／eVTOL／AAM／TIA／eIPP関連表題と、指定したeIPP公式記事の本文変更を確認。FAAの全公開情報の網羅検出や、非公開のTIA進捗率取得ではない。本文ハッシュの変化は確認待ちとして通知し、イベント本文は自動更新しない。

必須項目・日付・会社識別・件数・段階・数値範囲・公式URLを検査する。1情報源の失敗が他の正常データを消さない。events.jsonは情報変更時のみ更新。status.jsonは試行・成功日時、直接／代替／失敗と範囲を毎回記録する。無変更・取得失敗で通知を消さず次の変更で置換する。historyは全件保持する。掲載終了に伴う消失を変更として誤通知しないため過去取得分を統合する。

毎日14:17ごろ（日本時間）にGitHub Actionsで更新し、workflow_dispatchでも実行可能。同じPages/mainを使う既存ジョブとは既存concurrency groupで直列化する。既存Pages設定は変えない。サイトはnoindex。失敗時も状態を保存・公開してから失敗を通知する。

## 検証

`node --test joby/tests/update.test.mjs`、更新は `node joby/scripts/update.mjs`。WebKitは `node joby/tests/browser.cjs`（既存のPlaywrightを利用、アプリ依存なし）。
