# おやすみ

眠れない夜に「まだ寝れない…」「もう寝るよ」を伝える、スマホ優先のコミュニティです。添付見本の濃紺・月・淡い青とピンクのボタンを参考にしています。投稿・リアクション・今夜の人数はSupabaseで共有します。

## 起動

GitHub Pagesでそのまま配信できる静的HTML/JSです。ローカルではNode.js 22以上で `npm start` を実行し、http://localhost:3000 を開いてください。依存パッケージのインストールやビルドは不要です。匿名セッションの保存にはHTTP(S)の同じオリジンで利用してください。ローカルとGitHub Pagesの匿名アカウントは別になります。

## 実装済み

- 投稿は「まだ寝れない…」「もう寝るよ 🌙」「眠れないけど寝てみる 💤」「お先に寝ます 👋」の4つから選択。寝る報告は1タップでおやすみ完了画面へ
- 時刻付きタイムライン、投稿の絞り込み、自分の投稿削除
- タイムラインは全タブで投稿時刻から3時間未満の投稿のみ表示。起動・復帰・更新でも同じ判定を使い、表示中は期限到達で自動的に非表示になります。期限によるDB・履歴・集計データの削除は行わず、`night_date` と06:00境界は既存のままです。
- リアクションは「おやすみ 🌙」「いい夢を 💤」「また明日👋」「無理せずね☺️」の4つから選択（1投稿につき1つ、再度押すと解除、別の選択肢で変更）
- おやすみ完了画面、翌朝のおはよう記録、プロフィールの記録
- 「また明日 🌙」で操作のない静かな就寝終了画面へ。夜の再読み込みでも維持し、日本時間06:00に前夜の夜画面をおはよう画面へ切り替え。06:00〜12:00の起動／画面復帰でも表示（その日の記録後は再表示しません）。時間帯は `sleep-flow.js` の `rules` で変更できます。旧データに就寝時刻がない場合は夜の日付から判定します。
- 就寝・起床演出は `cat-scenes.js` の専用SVG（8毛色×寝ている／目覚めた姿）。プロフィールの5表情とは分離し、DBの選択値は変更しません。終了時は6.5秒でゆっくり暗くなり、猫と「おやすみなさい 🌙」だけを表示します。終了時刻から進行を判定するため再読み込みでも最初から再生しません。選択した毛色を就寝記録に端末内キャッシュし、翌朝も同じ猫を表示します。動きを減らす設定では暗くなるアニメーションを省略します。SQL変更は不要です。
- ニックネームのみ自由入力（1〜12文字、連絡先・明らかに不適切な表現は禁止、理由を短く表示）、ダークモード切り替え
- 猫の種類は「基本猫」8種・「野生猫」4種・「大ねこ」4種の3カテゴリ。表情は「おだやか・眠そう・あくび・寝れない・うれしい・きょとん」の6つ。個別PNGを共通の真円・1:1フレームで表示し、マイページ・投稿・相手プロフィールに反映
- Supabase匿名認証、別ユーザーとの投稿・リアクション・人数共有、操作後・画面復帰時・表示中30秒ごとの更新
- iPhoneのセーフエリア、キーボード操作、動きを減らす設定への配慮

他人への投稿・リアクションは選択式のみです。自由メッセージ・DM・個別チャット・フォロー機能はありません。現在の匿名アカウントの共有データを表示し、以前のlocalStorage `oyasumi-v1` は変更せず保持します。旧投稿・旧リアクションは共有DBへ移行せず、共有一覧には混ぜません。朝の記録・表示設定・おやすみ時点の人数は `oyasumi-local-v2` に端末内保存します。有効なローカル名は新しいプロフィールの初期名に使い、プロフィールが存在する場合はDBの名前を優先します。

ニックネームはフロントの既存検証とDBのRPCの両方でチェックします。全角の連絡先、不適切表現などを拒否し、表示はHTMLエスケープします。フロントは書記素単位、実行済みSQLはUnicodeコードポイント単位で1〜12文字を判定するため、長い結合絵文字などはDBで拒否される場合があります。DBの理由も入力画面に表示します。新規プロフィールの初期名がDBルールで拒否された場合は「ともを」を使用します。簡易ルールなので、すべての不適切表現・迂回表記の検出は保証しません。

人数は日本時間の正午〜翌正午の各ユーザーの最新投稿から集計し、寝る系3種類を「寝た」と扱います。実際の睡眠やオンライン状態の検知ではありません。人数の推移グラフは、今夜の投稿から15分ごとの実データと現在時点を集計します。削除した投稿は過去の推移からも除外されます。タイムラインと取得する自分の履歴はそれぞれ最新100件、プロフィールのおやすみ回数は全件から集計します。

匿名アカウントは端末ごとに異なります。別端末で同じ本人としての同期、メールログイン、Edge Function、既存データの移行、通知は今回の対象外です。ブラウザデータを消すと、その匿名アカウントには戻れません。

## Supabase接続

Supabase側で実行済みの `oyasumi_profiles` / `oyasumi_posts` / `oyasumi_reactions` と、`oyasumi_set_nickname` / `oyasumi_submit_post` / `oyasumi_delete_post` / `oyasumi_set_reaction` / `oyasumi_reaction_counts` / `oyasumi_tonight_counts` を使用します。Anonymous Sign-Insを有効にする必要があります。

接続設定は `supabase-config.js` にある公開URLとpublishable keyだけです。Secret key、service_role、DBパスワードは使用しません。書き込みは所有者チェック付きRPC経由、読み取りはRLSで制限します。Supabase公式SDK 2.117.2を `vendor/` に同梱し、外部CDNへの実行時依存はありません。ライセンスは `vendor/SUPABASE-LICENSE.txt` に含めています。

猫の毛色・表情機能を有効にするには、SQL Editorで `supabase/cat-appearance.sql` を実行してください。既存プロフィールに `cat_coat` / `cat_expression` を追加し、本人だけが変更できる `oyasumi_set_cat_coat` / `oyasumi_set_cat_expression` RPCを作ります。既存の名前・認証・投稿・リアクション・人数集計は変更しません。以前のユーザーは「三毛・おだやか」が初期値です。設定で8種類の毛色、マイページの大きな猫をタップして5種類の表情を選べます。毛色と表情は独立して保存します。SQL未実行でも既存の共有処理は動作しますが、表情の保存はできません。

最新見本に合わせた `cat-faces.js` の共通SVGに8種類の毛色と5種類の表情を重ねます。旧 `cat.svg` は削除しました。ユーザー画像アップロードは追加していません。以前の `cat-expressions.sql` は `cat-appearance.sql` に統合しました。以前のSQLを実行済みでも、そのまま追加適用できます。

## 動作確認

大ねこは `supabase/big-cats.sql` を適用後、`npm run test:big-cats` で4種×6表情、320/375/390/430px、Supabase実保存・別ユーザー共有・再読み込み・所有権・変更制限を確認します。詳細は `supabase/big-cats.md`。基本猫・野生猫の画像、既存の変更制限設定、投稿・集計・06:00境界は変更しません。

Node.js 22以上とMicrosoft Edgeを用意し、`npm test` を実行してください。追加パッケージは不要です。実際のSupabaseに接続するためネットワークが必要です。Windows以外では `EDGE_PATH` 環境変数にChromium系ブラウザの実行ファイルを指定してください。

`test-live.js` は別々の匿名ユーザーで共有とRLSを検証します。`test-browser.js` は全選択肢、匿名セッションの再利用、名前の検証、通信失敗・保存後の取得失敗、スクロールと入力途中の保持、旧localStorageの保持、朝の記録、320/390/430/1280pxでの表示を検証します。検証投稿は終了時に削除します。匿名認証アカウントとプロフィールは、権限の強いキーを使わないため残ります。

SQL実行後、8種類の毛色×5種類の表情の保存・別ユーザーへの反映・再読み込み・不正値や直接更新の拒否も検証します。SQL実行前に画面だけ確認する場合は `node test-browser.js --preview-cats` を使用してください。これは保存・共有テストの代わりにはなりません。

## 今夜の推移とコメント

SQL Editorで `supabase/tonight-trend.sql` を実行してください。既存の集計RPCと同じ今夜の日付を使用し、各時点までの各ユーザーの最新投稿を集計する認証必須RPCを追加します。個人別の推移や認証情報は返しません。既存RLS・投稿・リアクション・猫設定は変更しません。

`tonight-trend.js` の `messages` で5種類のコメント文言、`rules` で比較時間・変化率・確認回数・保持時間を変更できます。15分境界の確定サンプルだけを使用し、直近2点の平均と30〜60分前の平均の変化率を比較します。増加10%以上・減少10%以上・大きな減少30%以上を基本とし、絶対差2人未満は横ばいにします。2区間連続の確認、解除用の別閾値、切り替え後30分の保持で短期ノイズを抑えます。最低45分の連続観測が必要です。取得失敗時はデータ不足として既存機能を維持し、サンプル人数は表示しません。

4種類のリアクションには `supabase/reactions-four.sql` をSQL Editorで実行してください。既存3種類の値・RLS・既存RPCを保持し、CHECKの選択肢と追加RPC `oyasumi_set_reaction_v2` / `oyasumi_reaction_counts_v2` で `comfort` を扱います。新しい保存RPCは既存の本人・投稿・操作制限を通したうえで、同じトランザクション内で4種類目へ変更します。投稿の2ボタンは均等幅・同じ高さ、リアクションは2×2で配置し、既存の背景色は変更していません。
